## Known issues / decisions to revisit

* **ABS catalogue 5512.0 (annual GFS) migrated to data cubes.** `readabs::read_abs()` rejects it. I wired up `readabs::download_abs_data_cube()` as a fallback in `sbm_ingest_abs_gfs()`; the specific `catalogue_string` and `cube` args need ABS-current verification (the catalogue URL slug occasionally changes). Until then the reconciliation panel reports "no rows yet". This blocks the brief's "headline variables reconcile to within 2% of ABS GFS" success criterion.
* **ABS catalogue 5220.0 (state accounts)** errors inside readabs with `"cannot coerce type 'closure' to vector of type 'character'"` --- upstream readabs ↔ ABS issue. Per-GSP analytics return zero rows until this unblocks. Options: try `download_abs_data_cube()`; or hand-curate `data/extracted/abs_gsp.csv` and bypass the fetcher.
* **3 of 5 confirmed source URLs return 404** (NSW FBO 2023-24, NSW HYR 2024-25, VIC Financial Report 2023-24). Manual fix in `inst/document_registry.csv` --- open each in a browser, locate the current URL, paste it in.
* **275 of 280 registry rows have `source_url = NA`** ("URL TBD"). Intentional --- I deliberately did not fabricate URLs. Hand-populate as the project matures.
* **Placeholder CSVs under `data/extracted/`.** NSW + VIC headline-variable CSVs are present so the dashboard renders, but the values are PLACEHOLDERs. Replace with real extracted figures (rule-based via `tabulapdf` once parsers are written, or LLM-assisted via `sbm_extract_llm()` on a dev machine).
* **`tabulapdf` in Suggests not Imports.** It needs a working JDK at install time which I don't have here. Promote to Imports once Phase 2 extractors actively consume it.
* **Per-state parsers are stubs.** Each `R/extract/extract_<juris>.R` knows where to look (anchors per doc_type) but doesn't yet map line items to canonical variables. They're called via the framework but return NULL --- committed CSVs are the active extraction path. This is the highest-value follow-up work.
* **GitHub Pages deployment untested.** I built the workflow but didn't trigger it in this environment. First-run cold cache should take ~10--15 min per the Phase 0 spec.
* **DuckDB upsert** uses DELETE + reload because `dbAppendTable()` has no `ON CONFLICT`. Fine while small (<<1M rows projected).
* **Quarto execute-dir = project** is set so `tar_read()` and `tar_source("R")` work from any `.qmd` location.
